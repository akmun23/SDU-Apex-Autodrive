# SUBNET reference body model — progress (2026-10-04)

**Status: in progress.** The offline simulator is not yet accurate enough for full-lap raceline ranking, and no learned model or observer ablation has been promoted to MPC/production odometry. V7 is a high-steer specialist candidate but loses on practice; a simple hard switch did not fix that. A separate offline-only odometry ablation removes a large high-steer launch-speed error and is unchanged on the tested low-steer practice capture, but still needs broader validation.

This is a narrow SUBNET body-model comparator branch, not the workspace's only plant candidate. The broader [`BLACK_BOX_OFFLINE_PLANT_PROGRESS_20261003.md`](BLACK_BOX_OFFLINE_PLANT_PROGRESS_20261003.md) records WP28's strongest full-state effective teacher: it performs better on its two practice captures than the tested acceleration candidates, but still has meter-scale continuous drift and a 1.73 m 5 s high-steer position error. No candidate in either branch is accepted as a trustworthy full-lap simulator.

## WP33 whole-practice transfer check — complete for v1/v2; v3 checkpoint retained

The six-lap evaluation is free-running for the body model, with an independent command-to-actuator model for realistic command-driven rollouts. Feeding the model recorded future actuator feedback as an oracle barely changes its full-run errors, so actuator prediction is not the principal cause of the drift. On the two six-lap practice validation captures, v1 command-driven full-run position RMSE is 8.02/8.16 m, endpoint error 10.34/10.16 m, forward-speed RMSE 0.142/0.154 m/s, and yaw-rate RMSE 0.434/0.434 rad/s. The untouched three-lap blind capture baseline is 8.01 m position RMSE, 5.92 m endpoint error, 0.131 m/s forward-speed RMSE, and 0.425 rad/s yaw-rate RMSE. These results reject using v1 as a trusted full-lap optimizer plant.

V2 best epoch 9 lowered frozen open-plane position error (3.75 s: 1.959→1.434 m; 5 s: 3.199→2.222 m; 10 s: 9.285→5.709 m), but did not transfer as a global win: six-lap full-run forward-speed RMSE worsened from 0.142/0.154 to 0.274/0.316 m/s and position RMSE worsened from 8.02/8.16 to 8.69/9.54 m, while yaw-rate RMSE improved from 0.434/0.434 to 0.256/0.288 rad/s. Thus the model trades forward-speed accuracy for yaw accuracy on practice data; this is not sufficient for raceline time optimization.

V3 adds the high-steering r03 training capture and practice r02 (train) / r03 (validation) to the frozen base, preserving the original rows. Its first fit used uniform-window sampling, under which the 1,203 practice-r02 windows were only 0.28% of 436,094 training windows. That fit was intentionally stopped after 14 epochs rather than burning compute on a training objective that barely represented the lap domain. Best checkpoint is epoch 12, validation score 0.215895 on the v3 data/normalization; this score is not directly comparable to another dataset's score. The checkpoint and trace are retained in `native_subnet_fit_v3/`.

The corrected v4 fit used the frozen v3 dataset with run-balanced window sampling and run-macro whole-run validation. For 18 training runs, practice r02's expected batch share rose from 0.28% to 5.56% (20×). It plateau-stopped after 34 epochs: best at epoch 14, validation sim-NRMS 0.10958, then 20 stale epochs. Report/checkpoint are in `native_subnet_fit_v4_runbalanced/`. The v3 practice validation is development model-selection data; the blind three-lap practice run remains reserved. This change does not expose truth as a rollout input.

The practice evaluator now also records one-step and subsecond horizons (25 ms, 250 ms, 500 ms) alongside multi-second and full-run errors. This separates local transition error from recursively accumulated drift on exactly the same held-out runs.

The saved six-lap practice bags were also rechecked offline with the existing state-accuracy analyzer; this subscribes to nothing and uses IPS only as a score label. `/odom` position drift after a single initial alignment has p95/max 0.459/0.490 m on r02 and 0.254/0.342 m on r03. Thus the estimator does reduce accumulated error relative to raw odom, but nominal-practice localization is still not centimeter-accurate. These captures do not contain the open-plane high-steer conditions through the production localization stack; its behavior there remains unverified, and no production node was changed.

At 5 s, command-driven mean condition position RMSE is 1.44–1.46 m, forward-speed RMSE 0.278–0.284 m/s, and yaw-rate RMSE 0.130–0.132 rad/s; using future measured actuator feedback improves position only to about 1.40 m. The next model comparison must report `u`, `v`, yaw, and pose separately instead of relying on the path metric.

## WP35 pose-frame and 40 Hz integration audit — complete

Before attributing all pose discrepancy to the learned body dynamics, the recorded simulator pose was compared against the rigid-state velocity labels offline. Across 656,879 practice-r03 intervals, finite-difference pose lateral velocity agrees with the rear-axle label (`v_com - 0.15532*r`) to 0.037 m/s RMSE, versus 0.368 m/s if incorrectly treated as COM velocity. Comparing adjacent 25 ms body samples gives nearly identical joint velocity residual at the interval start and end (0.107 vs 0.109 m/s), so these data show no clear one-sample global timestamp shift. The rear-axle reference used by SUBNET is consistent with the pose labels.

The 40 Hz pose integrator convention does affect the truth-only floor. On 40 high-steer conditions, mean 5 s truth-state position RMSE is 0.092 m with interval-start twist, 0.018 m with midpoint twist, and 0.063 m with interval-end twist. On six-lap practice-r03 continuous integration the corresponding floor is 0.323/0.292/0.273 m; when each practice lap is truth-reinitialized, interval-end gives 0.081 m average position RMSE (midpoint 0.095 m; start 0.179 m). Thus one integration convention does not win on every regime. Re-scoring v4 practice-r03 across start/mid/end leaves its six-lap position RMSE essentially unchanged (0.886/0.887/0.887 m), and on high-steer the best v3-v4 distinction remains large (about 0.60 vs 1.16 m at 5 s under the mandated start convention; midpoint gives 0.64 vs 1.19 m). Integration alignment is a secondary sensitivity, not the dominant plant error; no production physics or model output was changed.

## WP36 longer recursive training — evaluated; candidate rejected

The 1 s training windows did not ensure 5–10 s path accuracy. V6 therefore fit 200 recursive samples (5 s) per training window on `body_sysid_v4.npz`, with 512 run-balanced updates per epoch and run-macro validation across 10 whole validation runs. Of 18 training runs, 14 contained at least one contiguous 5 s window; together they supplied 278,895 windows over -2.55 to 12.0 m/s, including high-steering samples. The other four short runs were excluded from this particular long-horizon fit because they cannot supply a 5 s sequence. V6 stopped after 25 epochs (12,800 updates, 28.2 min); best validation was epoch 21 at normalized score 0.14525, worse than v4's 0.09659. Validation rose to 0.346 at epoch 24 before partially recovering to 0.262 at epoch 25, alongside elevated training loss/gradient spikes. Run metadata now records the actual window/run counts and stop configuration.

Free-rollout evaluation rejects v6 as a general plant candidate. On the six-lap practice-r03 capture, command-driven 5 s position RMSE is 1.504 m versus 0.311 m for v4; full-run position RMSE is 1.839 versus 0.886 m, endpoint error 2.977 versus 1.439 m, and v6 also has higher full-run forward-speed, lateral-speed, and yaw-rate errors (0.181 vs 0.153 m/s, 0.0259 vs 0.0115 m/s, 0.0980 vs 0.0698 rad/s). The fixed-start validation cohort likewise gives v6 5 s/10 s position RMSE 2.413/6.095 m, versus v3 1.828/4.802 m and v4 2.290/6.058 m. On the two aggressive-turn captures, v6 has slightly lower 1 s position error than v4 (0.060/0.059 vs 0.067/0.063 m), but at 5 s it is worse than both v4 (1.286/1.300 vs 1.157/1.158 m) and v3 (0.613/0.592 m). Thus optimizing a 5 s training loss did not deliver robust path prediction; do not use v6 to rank racelines or integrate it into odometry/MPC.

## WP37 controlled long-horizon optimization-step trial — evaluated; not a global improvement

The isolated change was Adam learning rate `1e-3` → `3e-4`; dataset, seed, 200-step recursive objective, run-balanced sampling, 512 updates/epoch, and architecture stayed fixed. Training early-stopped after 46 epochs at the 20-epoch validation plateau. Best was epoch 26 at run-macro validation score `0.13378`, still worse than v4's `0.09659`; preserve v7 as a comparator, not a replacement.

Whole-run tests expose a domain tradeoff. On unseen practice r03, command-driven full-run position RMSE is `4.033 m` for v7 versus `0.886 m` for v4; endpoint error is `4.663` versus `1.439 m`. V7 improves `u` RMSE (`0.127` versus `0.153 m/s`) but worsens lateral speed (`0.0145` versus `0.0115 m/s`) and yaw rate (`0.124` versus `0.0698 rad/s`). At 5 s, position RMSE is `0.858` versus `0.311 m`. On the 384 fixed starts from six independent validation runs, v7 position RMSE is also worse at 1/2/5 s (`0.216/0.628/2.455 m`) than v4 (`0.186/0.544/2.290 m`); at 10 s v7 is slightly lower (`5.805` vs `6.058 m`), but body errors are worse and run-cluster intervals overlap. This does not validate v7 as a full-lap plant.

V7 does transfer better to aggressive-turn rollouts. At 5 s, command-driven position RMSE on high-steer r01/r02 is `0.310/0.303 m`, versus v3 `0.613/0.592 m` and v4 `1.157/1.158 m`. On high-steer r03 it is `0.316 m`, versus v3 `0.633 m` and v4 `1.171 m`. V7's high-steer `u` RMSE is lower, but its `v` and yaw channels are not uniformly better. R03's prediction score was evaluated only after v7 was frozen; that capture had already been inspected for a separate odometry diagnosis, so it is not an untouched final test and must not be reused for model selection.

An offline v4/v7 hard-switch prototype was tested on the same 20-condition high-steer captures. With a 1 s steering dwell it selected v7 for only ~5.4% of command-driven samples and produced essentially v4's 5 s error. Immediate switching with a `0.30 rad` entry / `0.25 rad` exit hysteresis selected v7 for ~14% and slightly worsened 5 s error (`1.156–1.188 m` versus v4 `1.157–1.171 m`). Latching v7 after first entry raised its use to ~20% but also slightly worsened error (`1.173–1.188 m`). Reject these hand-written switches; do not keep sweeping thresholds. A learned smooth regime-conditioned model remains a hypothesis, not an implemented improvement.

The final one-shot gate diagnostic uses the previous selected predicted body speed `>=7 m/s` and current available steering feedback `|steering|>=0.30 rad`; both experts advance on the same actuator inputs, and future truth is scoring-only. Across three 20-condition captures, it selected v7 on about 8.0% of command-driven samples (15.2% with recorded actuator feedback). At 5 s, command-driven position RMSE was `1.168/1.169/1.182 m` for the gate versus `1.157/1.158/1.171 m` for v4; the measured-feedback gate was `1.110–1.117 m` versus v4 `1.068–1.076 m`. It therefore does not improve on v4 and the hard gate is rejected; no more threshold sweeps are justified. V7 alone remains better on these high-steer captures at five seconds (`0.303–0.316 m`) but is worse during the first second and remains substantially worse on whole practice runs. These are not blind final results: r01/r02 informed v7 checkpoint selection, and r03 was already inspected for the odometry diagnostic.

The untouched final practice run `practice_unseen_blind_20261001_r01` remains reserved. No learned model was integrated into production odometry, localization, or MPC.

## WP38 reset-isolated production-odometry replay — diagnostic candidate only

The earlier full-bag replay carried one observer through 20 simulator resets and is invalid for per-test drift attribution. The corrected replay starts a fresh, source/config-hash-matched production observer for each selected segment. It plays only left encoder, right encoder, and IMU into the node in an isolated container/network; simulator truth is read from the raw bag only by the offline scorer. Stream cadence was ~39.96 Hz, timing faults and collisions were zero, and source alignment matched 99.63%/100% of samples in the two selected opposite-turn sequences.

The unmodified observer materially overestimates forward speed after a burst-rejected launch. In the high-speed/high-steer region (`u >= 7.5 m/s`, `|steering| >= 0.30 rad`), its `u` RMSE is `5.89/5.73 m/s` for the two turn directions. With one offline-only override, `wheel_burst_catchup_accel_mps2=0`, those errors fall to `0.181/0.179 m/s`; `v` RMSE is `0.0081/0.0077 m/s`. Relative-position RMSE over each entire 5.5–6.8 s segment falls from `14.25/10.96 m` to `1.01/0.49 m`; endpoint error falls from `23.84/20.19 m` to `2.16/0.73 m`. Yaw-rate error is effectively zero because gyro yaw rate is passed through. Residual position error is still material.

The packet trace supports a specific causal path: a burst-rejected wheel update leaves recovery pending while measured `ax` remains positive; the straight-motion branch first integrates `ax` into `speed_pred`, then the burst-window catch-up adds its configured acceleration on top. Disabling that *additional* term removes the large launch overshoot on both selected sequences. This is an offline parameter ablation, not a production change or proof that catch-up is unnecessary in every dropout case.

Nonregression check: on the clean six-lap practice capture `practice_model_validation_r03` (max speed `7.96 m/s`, max steering `0.283 rad`), the no-catch-up replay is bit-for-bit identical to the baseline across all 1,527 odometry outputs; the 1,312 scored active samples retain `u/v/yaw` RMSE `0.102/0.0101/~0 m/s,rad/s`. That capture does not cover the `|steering| >= 0.30 rad` regime, so it establishes no practice regression there, not high-steer track readiness.

The raw-capture scorer now supports a selected reset sequence, and the replay script supports a bounded timestamp-offset window with fresh observer lifecycle. Reports and replay bags are retained under the corresponding `live_runs/.../production_odom_replay_*` directories. Nothing was changed in simulator physics or production odometry configuration.
